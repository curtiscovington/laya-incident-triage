# Local Incident Triage

A reproducible, entirely local study of **Laya** and simple baselines on incident
ownership, current impact, and evidence quality. Inspired by Jev's typed-decision
interface; **this does not evaluate TypeSafe Jev**.

[Study report](study/artifacts/REPORT.md) · [Frozen protocol](study/PROTOCOL.md) ·
[Raw test predictions](study/runs/laya-test.jsonl) · [Study reproduction guide](study/README.md)

## Result

The study contains **576 synthetic records from 72 incident families**. Entire
families are assigned to training, development, or test; all eight related
variants stay together. The final test has **288 records from 36 families**.

| System | All-three exact accuracy | 95% family-bootstrap interval |
|---|---:|---:|
| Task-trained TF-IDF logistic classifier | 86.5% | 76.7–94.8% |
| Laya | 34.7% | 28.5–41.0% |
| Keyword rules | 22.9% | 16.0–30.2% |
| Training majority | 9.7% | 3.8–16.3% |

The classifier's paired advantage over Laya was **51.7 percentage points**
(95% family-bootstrap interval: **39.9–62.5 points**).

Accuracy did not establish dependable routing. The classifier's development-selected
policy routed 177 test cases and got 26 wrong: **14.7% routed error**, above its
5% development target. Neither raw nor calibrated Laya found a qualifying
development threshold. An all-review policy automates nothing.

![Held-out accuracy with family-bootstrap intervals](study/artifacts/accuracy.png)

**Scope:** condition templates are shared across splits, and the classifier gets
task-specific training while Laya does not. The labels are author-generated oracle
labels, not independently adjudicated real incidents. These are results on a
controlled synthetic task, not production reliability estimates or an architecture
comparison. No generative LLM baseline is included. See the report's limitations.

## Inspect the published study without downloading a model

Python 3.12 is the tested version. This path requires no model weights, server,
API key, or inference calls:

```bash
git clone https://github.com/curtiscovington/laya-incident-triage.git
cd laya-incident-triage
python3 -m venv .venv
.venv/bin/pip install -r requirements-analysis.txt
.venv/bin/python -m unittest -v
.venv/bin/python -m unittest discover -s study -p 'test_*.py' -v
.venv/bin/python study/run.py analyze
.venv/bin/python study/render_figures.py
.venv/bin/python study/verify_results.py
```

The saved TF-IDF model is a joblib artifact generated by this project and bound by
its SHA-256 in `study/runs/selection.json`. Load the artifact from this repository
only; joblib is not a safe format for untrusted files.

## Run Laya locally

Internet is needed once to install packages and obtain the public checkpoint.
All subsequent inference uses explicit local weights, with Hugging Face offline
mode enabled. `verify_offline.py` additionally rejects Python socket connections.

```bash
# In the same virtual environment:
.venv/bin/pip install 'torch==2.14.1+cpu' --index-url https://download.pytorch.org/whl/cpu
.venv/bin/pip install -r requirements.txt
.venv/bin/hf download convaiinnovations/laya model.safetensors encoder/config.json tokenizer/tokenizer.json tokenizer/tokenizer_config.json rl_agent_config.json --revision 55cf4c4ebb4ebe31b2550e8bdf3bd21b99753851 --local-dir models/laya

.venv/bin/python predict.py --text 'Database lock contention is confirmed. A subset of production orders is delayed; other operations work.'
.venv/bin/python triage.py --backend laya
```

`predict.py` also accepts `--file incident.txt` or piped text. It reports three
label distributions and an advisory routing/review recommendation. It never pages
anyone or changes infrastructure. Long inputs are rejected before the runtime
can silently truncate evidence. CPU is the tested backend; GPU use needs a
compatible PyTorch installation and separate validation.

`triage.py` runs the **original 20-case exploratory pilot**, not the main study.
Its 0.90 routing threshold is an untuned demo default. Results are written to new
output directories so existing evidence cannot be overwritten.

## Reproduce inference in the frozen study

[Study README](study/README.md) documents the exact sequence and resume checks.
The published `study/runs/` contains a completed run. Repeating inference should
use an isolated checkout/copy with those run outputs moved to a separate archive;
do not mix new predictions with the published run. The required order is:

```bash
.venv/bin/python study/run.py audit
.venv/bin/python study/run.py dev
.venv/bin/python study/run.py fit
.venv/bin/python study/run.py test
.venv/bin/python study/run.py analyze
.venv/bin/python study/render_figures.py
.venv/bin/python study/verify_results.py
```

The checked-in protocol freeze predates development inference. The selection file
predates test inference. The runner checks frozen source/data hashes, and inference
checks the downloaded weight hash. Changing frozen methods requires a new study
version or an explicit amendment. This was a **local content-hashed protocol
freeze**, not external preregistration. See [publication notes](PUBLICATION.md).

## Model and dependencies

- Model: [convaiinnovations/laya](https://huggingface.co/convaiinnovations/laya), English root checkpoint, 421M parameters.
- Weights revision: `55cf4c4ebb4ebe31b2550e8bdf3bd21b99753851`.
- Runtime: `laya==0.3.20`; CPU PyTorch, four threads, one fixed training warmup.
- Environment: [study/environment.lock.txt](study/environment.lock.txt), captured on Linux ARM64 / Python 3.12.
- Calibration: one development-fitted scalar per output, applied to the checkpoint's rounded probabilities.

The Laya runtime warns about a clamped temperature bucket for 11+ options. This
study uses only three or four options; that bucket is unused. The model card
itself describes zero-shot and calibration limitations.
